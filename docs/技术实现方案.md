> 项目：AI 热点监控工具（Pulse）  
> 更新日期：2026-06-03

---

## 1. 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| 前端 | React 18 + TypeScript + Vite | SPA，开发端口 5173 |
| UI | Tailwind CSS + 自定义 cyber 组件 | Dashboard / Settings |
| 后端 | Express + TypeScript | REST API，端口 3000 |
| 数据库 | Prisma + SQLite | 本地 `server/dev.db` |
| 实时通信 | Socket.IO | 热点更新、分析完成通知 |
| AI | DeepSeek API（OpenAI SDK 兼容） | 可选，无 Key 时降级 |
| 爬虫/搜索 | axios + cheerio 等 | 多平台 adapter 模式 |

## 4. 核心模块设计

### 4.1 热点采集（scraperService）

- 启动后延迟 3 秒注册各平台定时任务（间隔见 `.env`）
- 每个 scraper 实现 `fetchData()` + `parseData()`，输出统一结构
- 通过 MD5(title + source) 去重后 `createMany` 入库
- 入库后调用 `notifyTopicsUpdated()` 推送 WebSocket

### 4.2 关键词搜索（searchService）

- `POST /search` 接收 query，并行调用各搜索 adapter
- 结果可选 `save=true` 写入 `hot_topics`，自动 `autoClassify` 分类
- 返回各源 `statuses`（ok/count/error/latencyMs）

### 4.3 AI 分析（aiService + aiAnalysis 路由）

**关键设计：动态客户端**

```typescript
// aiService.ts — 每次分析时创建客户端，避免 Key 更新后仍用旧实例
function createOpenAIClient(apiKey?, baseUrl?) {
  return new OpenAI({
    apiKey: apiKey || config.deepseek.apiKey,
    baseURL: baseUrl || config.deepseek.baseUrl,
  });
}
```

**异步任务模型：**

1. `POST /ai/analyze` 校验 Key、topicIds（≤50），生成 taskId
2. 内存 Map 存储任务状态，`processAnalysisTask` 后台执行
3. 逐条调用 DeepSeek，结果 upsert 到 `ai_analyses`
4. 完成后 `notifyAnalysisComplete` → 前端 `onAnalysisComplete` 刷新

**分析输入：** 热点标题/内容/来源/指标 + 用户启用关键词组中的词

### 4.4 API Key 管理（aiConfigService）

| 操作 | 实现 |
|------|------|
| 启动加载 | `initAiConfigFromDb()`：`.env` 有 Key 则跳过，否则读 `users.apiKey` |
| 保存 | `saveAiConfig()` → 更新 DB + `applyRuntimeAiConfig()` |
| 删除 | `clearStoredApiKey()` → DB 置 null + 清空运行时 |
| 脱敏展示 | `getApiKeyHint()` → `sk-...末4位` |

存储位置：`users.apiKey`（单用户 `default_user`）

### 4.5 前端 Dashboard — 勾选分析

```
selectedIds: Set<string>   // 跨页保留
TopicCard checkbox         // 每条热点可勾选
工具条：全选本页 / 清空选择
AI ANALYZE (N)             // 仅提交 Array.from(selectedIds)
```

- 未勾选时按钮 disabled
- 超过 50 条前端拦截提示
- 分析中显示 ANALYZING...，WS 或 30s 超时后刷新

### 4.6 前端 Settings — 配置缓存

- `settingsData.ts`：60s 内存缓存 + lite 配置请求（`?lite=1` 跳过统计查询）
- API Key 输入框 type=password，保存后清空输入
- 支持 TEST CONNECTION、DELETE API KEY

### 4.7 WebSocket 事件

| 事件 | 方向 | 用途 |
|------|------|------|
| `connected` | 服务端→客户端 | 连接确认 |
| `hot_topic:updated` | 服务端→客户端 | 有新热点，触发 silentRefresh |
| `hot_topic:batch_update` | 服务端→客户端 | 批量更新 |
| `ai:analysis_complete` | 服务端→客户端 | AI 任务完成 |
| `ping` / `pong` | 双向 | 心跳 |

前端通过 `WebSocketContext` + `useWebSocket(pageId)` 按页面订阅，避免重复连接。

## 5. 数据模型（Prisma）

```
User ──< KeywordGroup ──< Keyword
HotTopic ──< AiAnalysis (1:1, topicId unique)
User ──< NotificationPref
```

**HotTopic 关键字段：** title, source, hash(unique), metrics(JSON string), category, rank

**AiAnalysis 关键字段：** relevanceScore, summary, importance, isReal, prediction(JSON), tokensUsed, cost

## 7. 配置优先级

| 配置项 | 优先级 |
|--------|--------|
| DEEPSEEK_API_KEY | 1. 进程环境变量 / .env  2. 数据库 users.apiKey |
