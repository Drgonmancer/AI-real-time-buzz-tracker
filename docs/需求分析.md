# 需求分析文档

> 项目：AI 热点监控工具（Pulse）  
> 版本：v1.0  
> 更新日期：2026-06-03

---

## 1. 项目背景

内容创作者、技术博主和运营人员需要持续跟踪全网 AI 与技术热点，但信息分散在百度、微博、B 站、GitHub、Hacker News 等多个平台。人工逐站浏览效率低，且难以快速判断一条热点是否值得跟进。

本项目旨在提供 **一站式热点聚合、关键词监控、可选 AI 智能分析** 的本地运行工具，帮助用户：

- 自动采集多平台热点并统一展示
- 按关键词跨平台搜索并入库
- 对选定热点进行 AI 相关性评分与摘要
- 通过 WebSocket 实时感知数据更新

---

## 2. 目标用户

| 用户类型 | 典型诉求 |
|---------|---------|
| AI / 技术博主 | 快速发现值得写稿、做视频的热点 |
| 运营人员 | 监控品牌词、行业词在各平台的传播 |
| 个人开发者 | 本地部署、低门槛使用，API Key 可选 |

## 3. 功能需求

### 3.1 热点采集与展示（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| F-01 | 定时从多数据源采集热点 | 后端启动后自动爬取，数据写入 SQLite |
| F-02 | Dashboard 列表展示热点 | 支持分页、来源筛选、分类筛选、排序 |
| F-03 | 混合排序模式 | 默认展示近 7 天热点，按 rank + 时间综合排序 |
| F-04 | 热点详情 | 可查看标题、来源、链接、热度指标、AI 分析结果 |
| F-05 | 实时更新 | 新热点入库后通过 WebSocket 通知前端刷新 |

**数据源（采集）：** 百度、微博、抖音、B 站、搜狗、GitHub、Hacker News、Reddit、Dev.to、Bing News、Google News（中/英/AI）、Twitter（需 Token）

### 3.2 关键词搜索（P0）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| F-06 | Dashboard 搜索栏 | 输入关键词后并行查询多平台 |
| F-07 | 搜索结果入库 | 新结果自动去重写入热点表 |
| F-08 | 搜索源状态反馈 | 展示各平台成功/失败及结果条数 |

### 3.3 关键词组管理（P1）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| F-09 | 创建/编辑/删除关键词组 | 设置页可管理，每组 1～20 个词 |
| F-10 | 启用/停用关键词组 | 仅启用组内的词参与 AI 相关性计算 |
| F-11 | 组名唯一 | 同一用户下组名不可重复 |

### 3.4 AI 智能分析（P1，可选）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| F-12 | 配置 DeepSeek API Key | 设置页可保存、测试、删除 Key；Key 持久化到数据库 |
| F-13 | **勾选后分析** | 用户在 Dashboard 勾选若干热点，仅对选中项触发分析 |
| F-14 | 单次分析上限 | 单次最多 50 条 |
| F-15 | 未配置 Key 时降级 | 返回 503，热点采集与搜索仍可用 |
| F-16 | 分析结果展示 | 相关性评分、摘要、情感、重要性、真伪判断、趋势预测 |
| F-17 | 分析完成通知 | WebSocket 推送 `ai:analysis_complete`，前端自动刷新 |

**AI 输出字段：**

- `relevanceScore`：0～100 相关性评分
- `summary`：中文摘要
- `importance`：low / medium / high / urgent
- `isReal`：是否为真实有价值信息（排除标题党、谣言）
- `sentiment`：positive / neutral / negative
- `prediction`：24/48/72 小时趋势预测

### 3.5 系统配置（P1）

| 编号 | 需求 | 验收标准 |
|------|------|---------|
| F-18 | 数据源状态展示 | 设置页展示各源 enabled / active 状态 |
| F-19 | API Key 安全 | 接口仅返回脱敏 hint（如 `sk-...abc1`），不返回完整 Key |
| F-20 | 删除 API Key | 用户可一键清除已存储 Key，保护隐私 |

### 3.6 非功能需求

| 类别 | 要求 |
|------|------|
| 部署 | 本地单机运行，Windows 双击 `start.bat` 即可启动 |
| 依赖 | Node.js 18+，SQLite 免安装 |
| 可选配置 | 无 API Key 亦可使用采集与搜索 |
| 性能 | 列表分页默认 20 条/页，API 响应 JSON |
| 安全 | API Key 存数据库 `users.apiKey`，前端 password 输入框 |

## 4. 用户故事

### US-01：浏览热点

> 作为博主，我希望打开 Dashboard 就能看到各平台最新热点，以便决定今天写什么。

### US-02：搜索关键词

> 作为运营，我希望输入「DeepSeek」后同时查 B 站、微博、搜狗等，以便扩充监控范围。

### US-03：勾选 AI 分析

> 作为用户，我希望先勾选 3～5 条感兴趣的热点再点「AI ANALYZE」，而不是一次性分析全部，以便控制 API 成本。

### US-04：配置 API Key

> 作为用户，我希望在设置页保存 DeepSeek Key 并能在不用时删除，以便保护账号安全。

### US-05：关键词组

> 作为用户，我希望维护「AI 大模型」「开源项目」等关键词组，以便 AI 分析时结合我的关注点打分。

## 5. 业务流程

### 5.1 热点采集流程

```
定时任务触发 → 各平台 scraper 拉取 → 去重(hash) → 自动分类 → 写入 hot_topics → WS 通知前端
```

### 5.2 AI 分析流程

```
用户勾选热点 → 点击 AI ANALYZE → POST /ai/analyze { topicIds }
→ 异步任务逐条调用 DeepSeek → 写入 ai_analyses → WS ai:analysis_complete → 前端刷新列表
```

### 5.3 API Key 配置流程

```
设置页输入 Key → PUT /config/ai → 写入 users.apiKey + 更新运行时 config
→ 服务重启时 initAiConfigFromDb 自动加载（.env 优先）

删除 Key → DELETE /config/ai/key → 清空数据库与运行时配置
```

## 6. 约束与边界

| 项目 | 说明 |
|------|------|
| 单用户模式 | 当前无登录，使用 `default_user` 承载配置 |
| 国际源 | Reddit、Google News 等需代理或 VPN |
| Twitter | 需 `TWITTER_BEARER_TOKEN`（twitterapi.io） |
| AI 成本 | 由用户自行承担 DeepSeek 调用费用 |
| 分析缓存 | 同一热点默认不重复分析（`forceRefresh=true` 可强制） |
